# Sipier Versioning System

Sipier uses a custom versioning system to communicate the scale and importance of each release.

The version number follows the general structure:

```text
vMAJOR.MINOR.PATCH
```

However, each number has a specific meaning within the Sipier project.

---

## Founder Version

The **Founder Version** is the current early release of Sipier.

This version is intended for the project's earliest users, testers, and supporters while the application is still being actively developed.

The Founder Version may contain:

* Experimental features.
* Incomplete functionality.
* Known bugs.
* Performance issues.
* UI changes.
* Frequent updates.
* Breaking changes.

The Founder Version represents the beginning of Sipier's development journey before the first official BetaTesting release.

---

## v1.0.0 BetaTesting

The next major milestone for Sipier is:

```text
v1.0.0 BetaTesting
```

This release marks the beginning of official public Beta testing.

The purpose of `v1.0.0 BetaTesting` is to provide a more complete version of Sipier to a wider group of users and testers.

This release is expected to focus on:

* Core application stability.
* Automation reliability.
* Macro recording and playback.
* User interface improvements.
* Bug identification.
* Performance testing.
* Windows compatibility testing.
* Installer reliability.
* User feedback.

Although this release uses the `v1.0.0` version number, the `BetaTesting` label indicates that the application is still undergoing active testing and may contain bugs or incomplete features.

---

## v1.0.0 — Major Application Update

A `v1.0.0` release represents a **major application update**.

Major updates may introduce significant changes to Sipier, including:

* Major new systems.
* Large feature sets.
* Major UI redesigns.
* Significant architectural improvements.
* Major automation improvements.
* Large workflow changes.
* Important performance improvements.

A major version update represents a significant evolution of the Sipier application.

---

## v0.1.0 — Feature Update

A `v0.1.0` release represents a **normal feature update**.

These releases may introduce new functionality without fundamentally changing the entire application.

Examples include:

* New automation features.
* New macro capabilities.
* New UI features.
* New customization options.
* New workflow tools.
* Improvements to existing systems.

Feature updates are expected to occur more frequently than major application updates.

---

## v0.0.1 — Bug Fix and Patch Update

A `v0.0.1` release represents a **small update or patch**.

These releases are primarily intended for:

* Bug fixes.
* Small corrections.
* Stability improvements.
* Minor performance improvements.
* Small UI fixes.
* Compatibility patches.
* Minor security fixes.

Patch releases generally do not introduce major new features.

# Versioning Philosophy

Sipier's versioning system is designed to make the scale of each update easy to understand.

The general principle is:

```text
Major Application Update
v1.0.0

Feature Update
v0.1.0

Bug Fix / Patch
v0.0.1
```

As Sipier continues to develop, the version number will communicate the relative scale of each release.

The exact content of each release may vary depending on development priorities, testing results, and user feedback.

# Important Note

Version numbers are used as a communication system for Sipier's development milestones.

They do not guarantee that every release will contain a specific number of features or changes.

The scope of each release may change based on:

* Development progress.
* User feedback.
* Bug reports.
* Security considerations.
* Testing results.
* Technical requirements.

The Sipier development team may adjust release plans when necessary.
